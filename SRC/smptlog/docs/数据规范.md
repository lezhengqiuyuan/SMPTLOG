# SMPTLOG 数据规范

本文档是**唯一权威**的字段与协议定义。代码、ADIF 导出、云端同步三者必须与此一致。

---

## 1. QSO（通联记录）

表名 `qsos`，主键 `uuid`（UUID v4 字符串）。

| 字段 | 类型 | 说明 | ADIF 映射 |
|---|---|---|---|
| `uuid` | TEXT PK | 全局唯一，创建后不变 | `_SMPTL_UUID` |
| `call` | TEXT | 对方呼号，原样保存（大写） | `CALL` |
| `call_norm` | TEXT | 归一化呼号（去 `/P` 等后缀），仅本地索引与判重用 | — |
| `qso_time` | INTEGER | 通联时刻，**UTC 毫秒时间戳** | `QSO_DATE` + `TIME_ON` |
| `freq_mhz` | REAL | 频率（MHz） | `FREQ`（受 FREQ 策略影响） |
| `band` | TEXT | 波段，由频率推导 | `BAND` |
| `mode` | TEXT | 模式 | `MODE` / `SUBMODE` |
| `rst_sent` | TEXT | 己方发给对方的 RST | `RST_SENT` |
| `rst_rcvd` | TEXT | 对方发给己方的 RST | `RST_RCVD` |
| `pwr_sent` | TEXT | 己方功率（W） | `TX_PWR` |
| `pwr_rcvd` | TEXT | 对方功率（W） | `RX_PWR` |
| `antenna` | TEXT | 天馈 | `MY_ANTENNA` |
| `rig` | TEXT | 设备 | `MY_RIG` |
| `qth` | TEXT | 对方位置 | `QTH` |
| `country` | TEXT | 国家/地区 | `COUNTRY` |
| `my_grid` | TEXT | 己方网格 | `MY_GRID_SQUARE` |
| `grid` | TEXT | 对方网格 | `GRIDSQUARE` |
| `qsl_status` | INTEGER | 0 未确认 / 1 已发出 / 2 已收到 / 3 已确认 | `QSL_SENT` / `QSL_RCVD` |
| `remark` | TEXT | 备注 | `COMMENT` |
| `weather` | TEXT | 天气 | `_WEATHER` |
| `repeater_id` | TEXT | 关联的中继台 id（可为空） | — |
| `repeater_call` | TEXT | 中继呼号快照 | `_RELAY_CALL` |
| `repeater_downlink` | REAL | 中继下行频率快照 | `_RELAY_FREQ` |
| `repeater_offset` | REAL | 上行偏移（带符号） | `_OFFSET` |
| `tone` | TEXT | 亚音 / 色码 | `_CTCSS` / `_DCSCODE` |
| `station_id` | TEXT | 电台档案 id | — |
| `station_name` | TEXT | 电台档案名快照 | `_STATION` |
| `my_call` | TEXT | 己方呼号快照 | `OPERATOR` |
| `created_at` | INTEGER | 创建时间（UTC 毫秒） | — |
| `updated_at` | INTEGER | **同步裁决依据**，值大者胜 | — |
| `deleted` | INTEGER | 墓碑标记 0/1 | — |
| `device_id` | TEXT | 最后修改设备 | — |

### 关键不变量

1. `updated_at` 单调不减；任何写入都必须刷新它。
2. `deleted=1` 的记录**不物理删除**（compaction 保留 90 天）。
3. `repeater_*`、`station_*`、`my_call` 是**快照**：中继台或档案后续被修改，不得影响历史记录。
4. `call_norm` 由 `Callsign.base(call)` 计算，仅用于索引，不参与同步。

## 2. Repeater（中继台）

表名 `repeaters`，主键 `id`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | UUID |
| `name` | TEXT | 显示名（必填） |
| `call` | TEXT | 中继呼号 |
| `downlink` | REAL | 下行频率 MHz |
| `offset_mhz` | REAL | 上行偏移，带符号（如 -7.6） |
| `tx_tone` | TEXT | 发射亚音 |
| `rx_tone` | TEXT | 接收亚音 |
| `mode` | TEXT | FM/DMR/C4FM/D-STAR… |
| `band` | TEXT | 由 downlink 推导 |
| `color_code` | TEXT | DMR 色码 |
| `reflector` | TEXT | 反射器 / 房间号 / 通话组 |
| `qth` | TEXT | 位置描述 |
| `locator` | TEXT | 网格（用于算距离方位角） |
| `open_time` | TEXT | 开放时间 |
| `note` | TEXT | 备注 |
| `is_favorite` | INTEGER | 常用置顶 |
| `times_used` | INTEGER | 使用次数（自动累加） |
| `last_used` | INTEGER | 最后使用时间（UTC 毫秒） |
| `created_at` / `updated_at` / `deleted` / `device_id` | | 同 QSO |

**上行频率 = `downlink + offset_mhz`**，不单独存储。

## 3. StationProfile（电台档案）

表名 `stations`，主键 `id`。字段：`name`、`my_call`、`my_grid`、`rig`、`antenna`、`power`、`qth`、`is_default`、时间戳与墓碑字段。

同一时刻建议只有一个 `is_default=1`。

## 4. ADIF 映射规则

### 频率策略（设置项 `adif_freq_policy`）

- `down`（默认）：`FREQ` 写**下行**频率 —— 电台屏幕显示的那个，便于与他人日志对齐
- `up`：`FREQ` 写**上行**频率（= 下行 + 偏移）

### 模式还原

- 数字模式常写作 `MODE:DATA` + `SUBMODE:FT8` → 还原为 `FT8`
- 未知模式回退 `FM`

### 自定义扩展字段

ADIF 规范允许以 `_` 开头定义用户字段，其他软件导入时忽略但不报错：

```
_RELAY_CALL  _RELAY_FREQ  _OFFSET  _CTCSS  _DCSCODE  _DMR_CC
_XREFL  _WEATHER  _STATION  _SMPTL_UUID
```

### 解析容错

- 字段长度声明与实际内容不符 → 记 `AdifParseError(offset, snippet, reason)`，跳过该字段/记录
- 中文备注：以 `utf8.decode(bytes, allowMalformed: true)` 读取，坏字节替换而非抛异常

## 5. 同步协议

### 5.1 云端对象布局

```
smptlog/{dataset}/dev/{deviceId}/meta
smptlog/{dataset}/dev/{deviceId}/shard/{yyyyMM}/{seq}
smptlog/{dataset}/dev/{deviceId}/oplog/{ts}
```

`dataset` ∈ `qso` / `repeater` / `station`。`meta` 内容：

```json
{ "device_id": "abc123", "rev": 1730000000000, "count": 12,
  "updated_at": 1730000000000, "shards": [] }
```

### 5.2 为什么不用全局 manifest

EdgeOne Blob（COS 协议）只提供 `x-cos-forbid-overwrite`（禁止覆盖已存在键），**没有 If-Match 条件写**，无法实现 CAS。
因此改为「每设备只写自己的前缀」：物理上不可能产生并发覆盖，读取时按 `updatedAt` 合并。

### 5.3 同步流程

1. `LIST {dataset}/dev/`（delimiter=`/`）发现全部设备
2. 对每台设备 `GET meta`，**必须走强一致域名** `blob-nocache.edgeone.site`（否则可能读到最长 60 秒前的旧值）
3. `meta.rev` 大于本地水位 → 拉取该设备的 `oplog/*` 与 `shard/*`
4. 合并进本地库，规则见 5.4
5. 把本地未推送变更写入自己的 `oplog/{ts}`，然后 `POST` 更新自己的 `meta`
6. oplog 累计 ≥ 500 条时压缩为 `shard`，删除已合并的 oplog 键

### 5.4 冲突规则

- 比较 `updated_at`，**大者胜**
- 败方整条记录写入本地 `conflicts` 表（含来源设备、双方时间）
- 界面顶部出现黄色提示条，可「恢复」或「丢弃」
- 合并必须**幂等**：同一 oplog 重复应用不产生重复记录

### 5.5 端到端加密

- 算法：AES-256-GCM
- 密钥派生：PBKDF2-HMAC-SHA256，12 万轮，16 字节随机盐
- 密文布局：`SLG1` + 盐(16) + IV(12) + 密文（含 16 字节认证标签）
- 加密后再 gzip；读取时先 gunzip 再解密
- 密钥与密码**只存本机**，绝不进数据库与导出文件

## 6. 安全铁律（不可违反）

1. API Token、同步密码、派生密钥 **绝不写入 SQLite**（库文件会被同步/导出）
2. 任何导出文件（ADIF / JSON / CSV）**绝不包含**上述凭据
3. Windows 用 DPAPI（`CryptProtectData`，当前用户）→ `%LOCALAPPDATA%\SMPTLOG\config\secrets.bin`
4. Android 用 Keystore（AES-GCM）→ `noBackupFilesDir`，由原生通道 `smptlog/vault` 提供
5. 日志与异常输出中的 Token 一律脱敏
6. 换设备必须重新填写 Token

## 7. 本地算法约定

| 算法 | 约定 |
|---|---|
| 网格 | Maidenhead 4/6/8 位；6 位为「LLnnLL」，8 位为「LLnnLLnn」 |
| 距离 | Haversine，地球半径 6371.0088 km |
| 方位角 | 初始方位角，0°=正北，顺时针 |
| 判重 | 归一化呼号 + 波段 + 模式 + `\|Δt\| ≤ 窗口分钟`（0/5/30/60 可配） |
| 日出日落 | NOAA 简化算法，返回值一律 UTC |

## 8. 平台限制

- Android `minSdk 26`，`targetSdk 36`（`platforms;android-37` 尚未发布，发布后改两处数字即可）
- Windows 优先加载系统 `winsqlite3.dll`：部分机器启用「智能应用控制（Smart App Control）」会拦截随包发布的未签名 `sqlite3.dll`（错误码 4551）
- 构建路径含非 ASCII 字符时，Gradle 与 Dart AOT 会因路径编码失败；需在纯 ASCII 路径下构建（项目使用 `E:\SMPTLOG_BUILD` 镜像目录）
